# Battery in the community themes: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every community theme draws the optional `state.power` from agent-screensaver v0.6.0, each in its own look.

**Architecture:** One small battery view (`powerView`, `powerWarning`) is written once in the skill's `craft.md` and copied into each theme part that draws it, the way the themes already copy their limit view. Favourite feeds it into one more spike (ground) and plate (board); the ring themes feed it into their own ring function. The preview gets a `power` URL parameter so every state can be shot.

**Tech Stack:** Plain ES5-style JavaScript in IIFEs, WebGL in Favourite's ground, the skill's `preview.html` and `shoot.mjs` (Node 22, Chrome), `scripts/check.mjs`.

**Spec:** [docs/history/specs/2026-11-15-battery-design.md](../specs/2026-11-15-battery-design.md)

## Global Constraints

- The field is optional: no `requires` change; with no `state.power` a theme draws exactly what it draws today.
- Battery only on the main display (`state.display === "main"`); it stays in privacy mode.
- Copy, exactly: `Battery`, `N%`, `Nm left` / `Hh Mm left` (no time when `minutes_left` is missing or 0), `Charging`, `Full` (at 100), `Plugged in`, warning `Battery N%: plug in, 1 agent is working` / `N agents are working`.
- `low` and `warn` are read from the field, never recomputed.
- Every part of a changed theme gets the same patch bump (check.mjs). The RAM theme is never touched.
- Commits: conventional, explicit paths only, `git -c user.email=1496522+stavgayer@users.noreply.github.com -c user.name=stavgayer commit`, no AI attribution. No push.
- Reference stills are for checking only and are not committed (`media/` is updated only when the owner asks).

## Review Focus

- `minutes_left` missing or 0 on battery: the detail is empty, no `undefined` or `0m left`. Covered by the `power=low` preset variant in Task 1 (`power=nominutes`).
- `percent` 100 while charging: says `Charging`, not `Full` (charging wins). Checked with `power=charging` set to 100 once by hand in Task 2.
- A battery with no limits (fresh install, no agent signed in): Favourite still gets one spike and one plate; ring themes show one ring. Preview param `nolimits=1` in Task 1.
- Many limits plus the battery (13 items): Favourite's battery past `maxSpikes` keeps its plate at the row end; ring rows still fit at 4:3. Shot with `limits=many` in Task 1.
- Warn while an agent needs you (`state=call&power=low`): the large card owns the screen; the warning line hides.

  - `plugged`: `{ on_battery: false, percent: 79, charging: false, ... }`

- Produces (preview): `nolimits=1` (empty `limits`) and `limits=many` (13 limits: the 4 today plus 9 more across claude, codex, cursor and an unknown `gemini`).
